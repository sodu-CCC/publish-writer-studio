# 码字工坊 · Writer Studio

[![CI](https://github.com/sodu-CCC/publish-writer-studio/actions/workflows/ci.yml/badge.svg)](https://github.com/sodu-CCC/publish-writer-studio/actions/workflows/ci.yml)

**本地优先的 AI 网文写作工作台** —— 用你自己的作品做检索增强（RAG），让 AI 的输出贴近**你本人的文风**。

📖 **产品文档**：[中文](docs/PRODUCT-GUIDE.zh-CN.md) ｜ [English](docs/PRODUCT-GUIDE.en.md)

> 内含：功能详解 · 操作说明 · 数据存储与隐私 · 常见问题 · **免责声明**

🏪 **要上架浏览器商店？** 上架材料包在 [`docs/store/`](docs/store/README.md) —— 含商店文案（中/英）、隐私政策（中/英）、权限用途说明、以及 5 张 1280×800 截图。

以 Chrome 扩展（Manifest V3）形式交付，也可以作为纯网页在本地运行。

> **数据不出本机**：没有后端、没有账号、没有遥测。稿件和 API Key 只存在你的浏览器里。

## ✨ 特性

### 写作工作台
- **书架**：竖排目录（封面 / 书名 / 梗概）＋ **检索**（书名 / 作者 / 梗概 实时过滤、结果计数）；点书弹出书目浮层查看章节
- 章节管理、自动保存、实时字数、每日目标、近 7 天趋势、快照历史（防手滑）
- 设定卡片：大纲 / 角色 / 设定 / **伏笔**（悬停浮层预览）
- 文本排版：字体 / 字号 / 行距 / **段落缩进（0–8 字符可调）** / 标题标记 / 一键整理缩进
- 主题：默认 / 护眼绿 / 护眼蓝 / 暗色 + 自定义主色
- **导入文本 = 直接新建一本书**：支持 `.txt` / `.md`，正文里的「第X章」自动拆成章节
- 导出单本 txt、全量 JSON 备份与恢复
- **查找替换**（写作台工具栏里的按钮，或 `Ctrl+F`）：本章 / **全书**两种范围 —— 改人名、统一术语一键完成
- **Agent 大纲梳理**：读已写正文 → 只提炼**重大剧情关键点** → 对比已有大纲 → 检出偏差 → 给出多个拓展方向与建议大纲，可一键写入大纲卡片
  - **增量梳理**：默认只梳理「上次之后」的新章节，进度自动记录，可重置
  - **范围可控**：仅新增 / 全部 / 最近 N 章
  - **偏差询问**：检出与大纲不符时，可选择「调整大纲以匹配剧情」或「生成剧情修改建议」
- **伏笔标注**：给正文里某段加虚线（**紧贴文字底部**、不覆盖首行两格缩进），点击该段浮出「伏笔思路」
  - 一条伏笔可同时标多段（用**换行或分号**分隔；逗号算片段内部标点）
  - 每条可单独**启用 / 取消当前选中**，临时失效而不丢文字
  - 卡片编辑弹窗是**非模态浮层**：可以一边在正文里选字，一边点「取当前选中」

### RAG 文风贴合（核心）
- **语料采集**：从你的作品、粘贴文本或 txt 导入
- **本地检索**：中文 bigram 分词 + **BM25** 倒排索引，零依赖、纯本地
- **风格画像**：平均句长 / 短句占比 / 段长 / 对话占比 / 标点习惯 / 人称分布 / 高频用语
- **生成时自动注入**：风格画像 + Top-K 相似片段作为范例

### AI 辅助
- **多厂商接入（自带 Key）**：DeepSeek / OpenAI / 通义千问 / 智谱 GLM / Kimi / 硅基流动 / 本地 Ollama，或任意 OpenAI 兼容端点
- **写作动作**：续写 / 润色 / 扩写 / 缩写 / 章纲 / 起名 / 角色卡
- 结果**必须手动采纳**，不会自动写入或发布
- **一键应用审稿意见**：Critic 指出问题后，点一下即可按意见重写草稿
- **内置写作规范**：提示词强制要求「对话归属清晰」—— 多人物同场时不许连续多段只用「他/她」，必须用姓名或动作标识说话人

### Agent 模式（人在环）
一句「帮我把这一章写完」，Agent 会自主完成：

```
Plan（自己决定要查什么资料）
  → Gather（调用本地工具取证）
  → Draft（分段生成）
  → Critic（自检打分 + 列出问题）
  → Revise（不达标才重写）
  → 产出草稿（等你确认）
```

暴露给模型自主选择的 8 个工具：作品信息 / 大纲 / 角色卡 / 设定卡 / 章节列表 / 当前章结尾 / 风格画像 / 语料检索。

三重约束：**最大步数**、**修订轮数上限**、**随时中断**。

## 🚀 安装

### 方式 A：Chrome 扩展（推荐，无需服务器）

1. 打开 `chrome://extensions/`
2. 右上角开启 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本仓库根目录
4. 点工具栏的「码字工坊」图标 → **打开完整工作台**

### 方式 B：纯网页本地版

```bat
双击 start-server.bat        （或：python serve.py）
```

窗口会打印实际访问地址（形如 `http://127.0.0.1:5173/`）。服务器会自动避开被占用的端口。

> 网页版内置 `/ai/chat` 反向代理，用于绕开浏览器直连大模型的 CORS 限制。

## 🌐 在 Microsoft Edge 中使用

Edge 基于 Chromium，**本扩展无需任何修改即可直接运行** —— 已用 Playwright 驱动真实 Edge 跑通全部 E2E 用例。

### 加载未打包扩展（立即使用）

1. 打开 `edge://extensions/`
2. 左下角开启 **开发人员模式**
3. 点 **加载解压缩的扩展**，选择本仓库根目录
4. 点工具栏的「码字工坊」图标 → 打开完整工作台

### 发布到 Edge 加载项商店

| 项 | 说明 |
|---|---|
| 注册地址 | https://partner.microsoft.com/dashboard/microsoftedge/ |
| 费用 | **免费**（Chrome Web Store 需 5 美元一次性注册费） |
| 审核时长 | 通常 1–7 个工作日 |
| 需要材料 | ZIP、图标、至少 1 张截图（1280×800 或 640×400）、描述、隐私政策 URL |
| **最大优势** | **国内可直接访问**，作者和用户都不需要梯子 |

> 💡 若主要面向中文用户，**Edge 加载项商店是比 Chrome Web Store 现实得多的渠道。**

### 兼容性说明

- `chrome.*` API 命名空间在 Edge 中完全可用，**无需改成 `browser.*`**
- Side Panel（`chrome.sidePanel`）需要 Edge 114+，与 Chrome 同步
- `manifest.json` 里的 `minimum_chrome_version` 在 Edge 上同样生效；若 Edge 商店审核建议移除，删掉该字段即可

## 📖 快速上手

1. **建作品** —— 书架 → 新建，填书名 / 作者 / 梗概
2. **建设定** —— 写作台左侧「设定」，至少各建 1 张大纲 / 角色 / 设定卡（**Agent 会用到**）
3. **写正文** —— 直接在编辑区写，自动保存
4. **采语料** —— 语料库 → 采集本书 / 粘贴 / 导入 txt
5. **看画像** —— 语料库左侧，检查风格指标是否符合你的写作直觉
6. **用 AI** —— 写作台右侧选动作生成，或点「Agent 模式」让它写完一整章

> 💡 **画像准不准，取决于你喂什么。** 想让它像你，就采集**你自己真正写的正文**。

## 🏗 技术栈

- **Chrome Extension Manifest V3**：Service Worker、Side Panel API
- **原生 ES Modules**（无框架、无打包器、**运行时零第三方依赖**）
- **IndexedDB**（异常时自动降级 localStorage）
- **自研 RAG**：中文 bigram 分词 + BM25 + 文体计量学画像
- **OpenAI 兼容协议**多厂商适配层
- **Python 标准库**本地服务 + AI 反向代理
- CSS 自定义属性主题系统

运行时代码约 **5,500 行**（含测试与自检工具约 6,800 行），**零构建步骤**。
扩展本体不含任何运行时依赖；ESLint / Playwright 仅作为开发期工具存在。

## 🔒 隐私与合规

**本工具在设计上刻意避开了若干风险边界：**

- ✅ **纯本地**：稿件与密钥只存本机，无后端、无遥测
- ✅ **自带密钥（BYO-Key）**：模型由使用者自行申请与配置，本项目不提供模型服务
- ✅ **不注入第三方网站**：无 content script，不修改任何外部站点
- ✅ **不自动发布、不自动回写**：AI 结果只进编辑框，采用与否由使用者决定
- ✅ **不提供"去 AI 痕迹"功能**：不涉及隐藏、规避或伪造 AI 生成事实
- ✅ **AI 使用留痕**：本地记录调用日志，便于按平台要求**主动声明**

> ⚠️ **使用者须知**：若将 AI 生成内容用于签约或公开发布，请遵守所在平台规则，以及
> 《人工智能生成合成内容标识办法》（2025-09-01 施行）关于**主动声明**的要求。
> 请勿使用本工具生成违法违规内容。

## 🧪 开发与测试

### 静态自检（无需安装任何依赖）

```bash
node tools/check.mjs
```

会检查 8 项：JS/Python 语法、manifest 合法性、**DOM 选择器一致性**、资源引用完整性、硬编码密钥、
禁止文件（逆向产物等）、**扩展目录命名限制**（Chrome 不允许 `_` 开头的名字）。

### 代码风格与端到端测试（需要 Node.js 18+）

```bash
npm install                  # 安装开发期依赖（ESLint / Playwright）
npx playwright install chromium

npm run check                # 静态自检
npm run lint                 # ESLint
npm run test:e2e             # 端到端测试（真实 Chromium 加载扩展）
npm run ci                   # 一次跑完上面三项
```

E2E 测试用真实浏览器打开工作台，**共 36 个用例**，并断言**不产生控制台错误**：
`smoke.spec.js` 覆盖 28 条链路（启动渲染、新建作品、三视图切换、字数统计、主题切换、语料库自检、
次级菜单点外关闭与窗口激活保护、段落缩进整理、查找替换、伏笔标注/启停/清空、导入成新书、书架检索、
顶栏当前页指示、非模态弹窗边选边取 …）；`agent.spec.js` 覆盖 8 条 Agent 全流程
（Plan→Gather→Draft→Critic→Revise、人在环不自动写入、对话归属规范、一键应用审稿意见、
大纲梳理与增量进度、弹窗状态重置、AI 插入选区语义）。

> 说明：Chrome 137+ 移除了 `--load-extension` 命令行开关，无法再自动加载未打包扩展，
> 因此 E2E 针对**网页版**（同一套 `app/` 代码，覆盖约 95% 业务逻辑）。
> 扩展专属部分（Service Worker 代理、sidePanel）需人工验证。
> 本地若不想下载 Chromium，可设 `PW_CHANNEL=chrome` 复用系统已装的 Chrome。

> 💡 本项目**运行时零依赖**是有意为之：扩展本体不引入任何第三方库，只有开发期工具放在 `devDependencies`。
